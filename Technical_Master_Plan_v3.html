3. Podela: Ana vs ZOTA

KomponentaŠta radiŠta ne sme da bude
ANA v2Komunikuje, sluša, govori, vodi prvi kontakt, nudi QR nastavak, vodi retail i info tokNe sme biti vlasnik state istine, case logike ili procesa

Jedna rečenica za ceo tim: Ana govori. ZOTA odlučuje.

4. Tehnološki stack

Backend Core

Python 3.12+ i FastAPI za ZOTA, Ana conversation layer, pricing, admin i orchestraciju.

Data

PostgreSQL kao source of truth za case, retail, decisions, audit i agregate.

Session / Queue

Redis za session cache, short-lived state, queue signalizaciju i rate limiting.

Device Frontend

React kiosk app za tablete i ekrane; kasnije Flutter/native samo ako zatreba.

Voice

Twilio kao gateway + voice-service + STT/TTS provider + fallback tok.

Assets

Object storage i CDN za audio, avatar assete, dokumenta i export.

Ne raditi prerano: tri jezika, rani mikroservisi, Kubernetes bez potrebe i hiper-kompleksan 3D avatar pre core logike.

8. ANA v2 Retail Core

ANA v2 u trafici ili prodavnici je retail AI interfejs koji zna artikle, cene, akcije, reklame, pakete i QR nastavak. Nije samo prodavac paketa.

Retail Catalog Service

Artikli, cene, kategorije, zalihe i lokacijske razlike.

Service Catalog Service

Internet/TV/uslužne ponude, bundle logika i prodajni tokovi.

Knowledge Service

FAQ, radno vreme, lokacijski odgovori i dozvoljene formulacije.

Campaign & Ad Engine

Idle mode reklame, raspored prikaza, prioritet kampanja i promo sadržaj.

Conversation Service

Voice/text interakcija, intent detection, FAQ, up-sell i capture logika.

QR Bridge + ZOTA Connector

Prenos sesije na telefon i slanje svega važnog u ZOTA case sloj.

Kritično: Ana v2 ne sme improvizovati cene, dostupnost ili osetljive odgovore. Sve dolazi iz kontrolisanog source-of-truth backend-a.

13. Timska struktura i senioriteti

Za profesionalni tim ne treba “gomila programera”, već jasno podeljene odgovornosti. Model ispod je namenjen timu koji želi da izgradi ozbiljan sistem bez haosa.

Minimalni ozbiljan tim za pokretanje

1. Lead Architect / CTO

Vlasnik arhitekture, standarda, odluka o podeli servisa, code review za kritične module i tehnički kvalitet po fazama.

2. Senior Backend Engineer — ZOTA Core

Case engine, state machine, decision layer, orchestration, admin API.

3. Senior Full-Stack / Device Engineer

ANA v2 kiosk app, device lifecycle, QR bridge, frontend state i device UX.

4. Senior Voice / Conversation Engineer

Twilio integracija, STT/TTS, voice session flow, fallback logika, prompt/rule orchestration.

5. Senior Platform / DevOps Engineer

Deploy, CI/CD, observability, backup, secrets, environments, uptime.

6. Product / Delivery Owner

Prioriteti, acceptance kriterijumi, scope kontrola, cross-team koordinacija.

16. Appendix: ZOTA implementacija

Osnovni tok: event → case → decision → action → result → next state
JezgroImplementaciona svrha
Case EngineCreate case, merge case, reopen case, attach event, attach message, close case
State EngineBusiness stanje: gde je case, šta čeka, šta je blokirano, šta je sledeće dozvoljeno
Decision EngineRule engine + scoring + AI suggestions za next action
Action OrchestratorPoruka, task, pricing call, offer, process trigger, escalation
Memory / Event LedgerPotpun trag svega što se desilo nad slučajem

Obavezna stanja: NEW_INQUIRY, QUALIFYING, WAITING_FOR_DATA, READY_FOR_OFFER, OFFER_SENT, WAITING_CUSTOMER_CONFIRMATION, PROCESSING_INTERNAL, VERIFICATION_PENDING, COMPLETED, LOST, ON_HOLD

Implementaciona poruka za glavni tim: Ne gradimo više chatbot sistem. Gradimo case-driven operating system u kome svaki događaj ulazi u Case, ZOTA donosi odluku nad stanjem Case-a, aktivira sledeću akciju i vodi proces do ishoda.

17. Reference model rada ozbiljnih firmi

Ovaj staffing i governance model je oslonjen na obrasce koje koriste ozbiljne platformske i produkcione organizacije: jasna podela odgovornosti između proizvoda i inženjeringa, odvojena platform/reliability funkcija, dogovorene odgovornosti između timova i postepeni prelaz iz product-build faze u production-scale operaciju.

  • Google SRE: različiti modeli organizacije SRE timova i fokus na odgovornosti, granice i smanjenje operativnog toila.
  • AWS Well-Architected: operational excellence i reliability kao stalni deo dizajna i rada sistema, uz jasno definisane dogovore između timova.
  • GitLab handbook: jasna podela između Product “what/why” i Engineering “how/when”, uz posebne infrastrukturne i delivery funkcije.
  • Stripe engineering i platform primeri: shared platform i core infrastructure timovi koji omogućavaju proizvodnim timovima da brzo grade na stabilnoj osnovi.
